# pain-point-tutorial

> 描述一个常见痛点 → 拆穿核心问题 → 分步教程 → 用数据确认收益 → 抛球行动召唤

诺鸭船长那篇《为什么你的 AI 写不出好文章？我的 Skill 自动化长文创作方法》是这个 recipe 的标杆样本。

## 适用判断

- **文章类型**：痛点解决
- **推荐钩子类型**：场景认领（开头让读者觉得"这就是我"）
- **推荐情绪模板**：共鸣→认知（开头共情吐槽，中段冷静拆解，结尾微高潮俏皮）
- **不推荐场景**：
  - 故事叙事（这个 recipe 不留情节空间）
  - 信息差类（这个 recipe 假设读者**已经在受痛点折磨**，不是"教你一个新东西"）
  - L0 共识类（没痛点 = 没驱动力）

## 主结构（按段落）

| # | 段落任务 | 推进器 | 字数占比 |
|---|---|---|---|
| 1 | **痛点切入**：用 1-2 个画面级事例描述常见现象，让读者认领 | 用第二人称"你有没有发现…" | 10-15% |
| 2 | **拆穿核心判断**：单句成段抛出"问题出在哪？说穿了，X，而不是 Y" | 反问 + 单句段 | 5% |
| 3 | **方案铺开**：宣告"我搭了一套 XXX"，给读者一个可命名的方法/工具 | 给方法起名（命名 = 让读者记住） | 5% |
| 4 | **分步教程**：每个 step 单独成节，标题用判断句不用名词 | 每节开头反问引入 + 节末给"为什么这一步必要" | 50-60% |
| 5 | **收益数据**：放具体数据（前后对比 / 量化提升） | 用数据 + 一句更深的认知（"效率不是最重要的收获，最重要的是…"）| 10% |
| 6 | **行动召唤 + 抛球**：教读者怎么自己起步，结尾抛球留互动 | 不喊关注，留俏皮一句作收 | 10-15% |

## 情绪曲线

```
平 → 共鸣（吐槽痛点）→ 平稳（铺方案）→ 平稳（分步）→ 微上扬（数据）→ 微高潮俏皮（抛球收尾）
```

整体冷静，**只允许结尾一处情绪高点**（如诺鸭那篇结尾的"比小时候玩的游戏王还爽"）。

## 争议级别建议

**L1**——必须有"反共识"成分（"问题不在 X，是在 Y"），但不要走 L2。
- L0：没痛点感 → 文章无传播力
- L2：拆穿过狠 → 评论区会撕

## 素材预检（在通用门槛之上）

通用门槛之外，这个 recipe **额外要求**：
- **必须有"我自己跑过的数据"**：用前 vs 用后的具体数字（时间 / 数量 / 质量百分比）。引用别人的数据不算。
  - 例：诺鸭文里"4-6 小时 → 40 分钟，效率提升 80%"
- **方案必须有名字**：起一个让读者能记住的命名（noah-writing / noah-title）。"我的 AI 写作方法" 不算名字。
- **分步教程的每一步必须有"why"**：不只是说"做 X"，要说"为什么这一步必要 / 跳过会怎样"。

## 风格搭配建议

- **profile：noahduck283** — 理由：第二人称共鸣 + 单句段拆穿 + 「」概念强调，正是这个 recipe 的天然搭档
- **profile：default** — 也可，但开头钩子要手动改成第二人称
- **不要踩的雷**：
  - 长句 + 书面语过重 → 拆穿那一段会出戏
  - 文白夹杂 → 跟"画面级事例"的画面感冲突
  - 结尾喊关注 / 求转发 → 跟"抛球收尾"互斥
